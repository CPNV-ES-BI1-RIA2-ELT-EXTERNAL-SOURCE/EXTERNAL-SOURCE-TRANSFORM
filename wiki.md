# Python

This page aims to explain why we've selected Python with FastAPI for our service. The decision is based on technical advantages, ecosystem alignment, and the "needs" of the global project. Below are the key reasons for this choice.

## Flexibility

Python excels in handling data processing tasks, and its vast ecosystem offers numerous libraries for connecting to various data sources, such as:

* Databases
* APIs
* Data manipulation
* clouds
## Type Hinting

Python’s support for type hinting improves code clarity and maintainability. FastAPI builds on this feature by using type hints for:

* Automatic request validation
* Documentation generation

This ensures our code is robust and easy to debug, reducing potential errors early in development.

## Great Documentation

FastAPI is renowned for its excellent documentation, which:

* Provides clear and concise examples
* Covers a wide range of use cases
* Simplifies onboarding for new developers

Python’s own extensive documentation further supports developers in mastering the language and its libraries.

## Widely Used in the Global Project

The choice of Python with FastAPI aligns with the technology stack used by other teams in our global project.

This brings the following advantages:

* Easier knowledge sharing
* Consistency in tools and practices
* Simplified integration of microservices across teams

This alignment ensures smoother collaboration and compatibility within the larger ecosystem.

## Scalability and Performance

FastAPI is built on top of Starlette and Pydantic, making it:

* Highly performant due to asynchronous support
* Scalable for handling high-concurrency applications

This makes it a future-proof choice for our growing project requirements.
